# 商户结算业务规则

> 适用范围：payment-settlement-service
> 最近修订：2026-05-12（v3.2，费率下调后同步）

## 1. 结算周期

- 普通商户为 **T+1**：交易日 24:00 截单，次日 10:00 发起结算。
- 风控标记商户（`merchant.risk_level >= 2`）为 **T+7**，且必须人工复核后放款。
- 节假日顺延，顺延期间不计息。

## 2. 金额与精度

**所有金额一律以「分」为单位，使用 64 位整型存储与计算，任何环节禁止使用浮点类型。**

历史上曾因使用 `double` 累加导致对账差异（见 `bug-history.md` INC-2024-07），此后列为红线。

四舍五入规则：

- 手续费计算结果若有小数分，**一律向下取整（截断）**，差额由平台承担。
- 严禁使用「四舍五入」或「向上取整」，会导致多收商户手续费，属于合规问题。

## 3. 费率

| 商户类型 | 费率 | 说明 |
|---|---|---|
| 标准商户 | 0.6% | 2026-05 由 0.8% 下调 |
| 大额商户（月流水 ≥ 500 万元） | 0.38% | |
| 公益类商户 | 0% | 需资质审核 |

**费率不得硬编码在代码中**，必须从 `merchant_fee_config` 表读取，以便运营调整。

## 4. 最小结算金额

单笔结算净额（扣除手续费后）**必须大于等于 100 分（1 元）**，低于该金额的不发起结算，累计到下一周期。

原因：银行侧对小额代付收取固定成本，低于 1 元会造成亏损。

## 5. 结算状态机

```
PENDING → PROCESSING → SUCCESS
                    ↘ FAILED → PENDING（人工重试）
```

- 只有 `PENDING` 可以被发起。
- `PROCESSING` 状态严禁重复发起，必须依赖幂等键拦截。
- `SUCCESS` 为终态，不可回退。

## 6. 币种

当前仅支持人民币（CNY）。任何非 CNY 的结算请求必须拒绝，不得按 1:1 处理。
