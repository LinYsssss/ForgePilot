# 多租户隔离规范

> 适用范围：tenant-user-center
> 最近修订：2026-06-03

## 1. 核心原则

本服务是**多租户共享库**架构：所有租户的数据存在同一套表里，靠 `tenant_id` 隔离。

> **这意味着少写一个 `tenant_id` 条件，就是一次跨租户数据泄露。** 不是「可能」，是必然 —— 因为不同租户下的自增主键会重叠。

## 2. 强制约束

1. **所有表必须含 `tenant_id`**，且为复合索引首列。
2. **所有查询必须带 `tenant_id` 过滤**，包括 `count`、`exists`、`delete`、`update`。
3. `tenant_id` **必须来自认证上下文**，不得来自请求参数 —— 否则等于让调用方自选租户。
4. 跨租户操作只允许平台管理员执行，且必须走独立的、显式标注的接口。
5. 任何 `JOIN` 都要确认两侧的 `tenant_id` 一致，仅靠外键防不住交叉归属。

## 3. 代码约定

- 数据访问层统一经 `TenantScopedRepository`，它会强制注入 `tenant_id`。
- **禁止绕过该层直接拼 SQL**。
- 单元测试必须包含「B 租户读不到 A 租户数据」的反向用例。

## 4. 缓存

缓存键必须包含 `tenant_id`。曾发生过缓存键只用 `user_id` 导致跨租户命中的事故，见 `bug-history.md` INC-2025-04。

## 5. 导出与报表

批量导出接口风险最高，因为一次泄露的是整表。导出必须：

- 强制 `tenant_id` 过滤；
- 记录审计日志（谁、何时、导出了多少行）；
- 限制单次导出行数上限 10000。
