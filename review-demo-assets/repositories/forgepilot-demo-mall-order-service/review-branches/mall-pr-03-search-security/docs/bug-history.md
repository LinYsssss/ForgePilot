# 历史 Bug 记录

> 每条都对应一条已固化的规则。**新代码重复同类问题视为高危。**

## BUG-001 未支付订单被发货（2025-03，损失约 4.2 万元）

**现象**：37 笔未支付订单被发货，商品已出库。

**原因**：`OrderService.shipOrder` 只判断了 `status`，没有判断 `pay_status`。这两个是独立字段，订单可能处于 `WAIT_SHIP` 但支付状态仍是 `UNPAID`。

**修复**：发货前增加 `pay_status = PAID` 校验。

**固化规则**：见 `order-flow.md` 第 2 节，发货必须同时校验 `status` 与 `pay_status`。

---

## BUG-002 管理接口越权访问（2025-06）

**现象**：普通用户构造请求调用了管理端强制发货接口。

**原因**：新增的 `/admin/order/**` 接口只加了登录校验，没有角色校验。

**修复**：补充 `ADMIN` 角色校验。

**固化规则**：见 `security-policy.md`，管理端接口必须校验角色；「已登录」不等于「已授权」。

---

## BUG-003 订单详情越权查看（2025-08）

**现象**：用户遍历订单 ID 看到了他人订单，含收货地址与手机号。

**原因**：`getOrderDetail(orderId)` 直接按 ID 查询，未校验订单归属。

**修复**：查询后校验 `order.user_id == currentUser.id`，不匹配返回 403。

**固化规则**：见 `order-flow.md` 第 5 节。

---

## BUG-004 SQL 注入（2025-09）

**现象**：安全测试发现订单搜索接口可注入。

**原因**：搜索关键字直接拼接进 SQL。

**修复**：改用参数绑定。

**固化规则**：见 `security-policy.md`，禁止拼接 SQL。

---

## BUG-005 重复发货（2025-11）

**现象**：网络重试导致同一订单发货两次，产生两个运单。

**原因**：发货接口无幂等控制，仅靠前端禁用按钮。

**修复**：发货时以 `status = WAIT_SHIP` 作为条件更新，更新行数为 0 则视为已处理。

**固化规则**：见 `order-flow.md` 第 6 节。

---

## BUG-006 金额精度丢失（2026-01）

**现象**：部分订单实付金额比应付少 1 分。

**原因**：优惠计算过程中用了 `double`。

**修复**：全程整型运算，单位「分」。

**固化规则**：见 `order-flow.md` 第 4 节。
