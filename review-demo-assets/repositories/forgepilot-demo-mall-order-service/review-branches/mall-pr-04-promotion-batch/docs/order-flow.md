# 订单业务流程

> 适用范围：mall-order-service
> 最近修订：2026-04-18

## 1. 订单状态机

```
CREATED → PAID → WAIT_SHIP → SHIPPED → COMPLETED
   ↓        ↓         ↓
CANCELLED  REFUNDING  CANCELLED（仅未发货可取消）
```

- `CREATED`：下单成功，未支付。超过 30 分钟未支付自动取消。
- `PAID`：支付成功，等待商家备货。
- `WAIT_SHIP`：备货完成，可发货。
- `SHIPPED`：已发货，不可取消，只能走退货流程。
- `COMPLETED`：确认收货或超时自动确认。

**状态只能沿箭头方向流转，任何跳跃都属于缺陷。**

## 2. 发货规则（重点）

发货前必须**同时**满足：

1. 订单存在且未被逻辑删除；
2. `pay_status = PAID` —— **支付状态与订单状态是两个独立字段，必须分别校验**；
3. `status = WAIT_SHIP`；
4. 收货地址已填写且未被风控标记。

发货成功后：`status` 置为 `SHIPPED`，写入 `shipped_at`，并记录操作人。

> 历史上 BUG-001 就是只判断了 `status` 没判断 `pay_status`，导致未支付订单被发货。见 `bug-history.md`。

## 3. 取消规则

- 仅 `CREATED`、`PAID`、`WAIT_SHIP` 可取消。
- `SHIPPED` 之后禁止取消，必须走退货。
- 已支付订单取消需同步发起退款，退款失败订单不得置为 `CANCELLED`。

## 4. 金额

- 订单金额字段 `amount` 单位为**分**，整型存储。
- 优惠券抵扣、运费、实付金额分别独立字段，不得合并计算后再拆分。
- 任何金额计算禁止使用浮点类型。

## 5. 权限边界

- 用户只能操作**自己的**订单。仅校验「已登录」不构成授权。
- 管理端接口（`/admin/**`）必须校验 `ADMIN` 角色。
- 任何按订单 ID 直接查询的接口，都必须校验该订单归属于当前用户，或调用方具备管理员角色。

## 6. 并发

- 发货、取消、退款接口必须防重复提交，依赖数据库唯一键或条件更新，不得只靠前端禁用按钮。
