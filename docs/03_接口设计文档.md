# 代码仓库智能审查平台接口设计文档

## 1. 接口约定

### 1.1 基础路径

```text
/api
```

### 1.2 认证方式

登录成功后，前端需要在请求头中携带 JWT：

```http
Authorization: Bearer <token>
```

### 1.3 统一响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "b6d3f1a7"
}
```

### 1.4 分页响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [],
    "page": 1,
    "size": 10,
    "total": 100
  }
}
```

### 1.5 常用错误码

| code | 说明 |
| --- | --- |
| 0 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或 Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突 |
| 429 | 请求过于频繁 |
| 500 | 系统内部错误 |
| 6001 | Git 仓库访问失败 |
| 6002 | 审查任务不存在 |
| 6003 | 文档向量化失败 |
| 6004 | AI 调用失败 |
| 6005 | AI 输出解析失败 |

## 4. 仓库接口

### 4.1 绑定仓库

```http
POST /api/projects/{projectId}/repository
```

请求：

```json
{
  "repoUrl": "https://github.com/example/mall-order-service.git",
  "provider": "GITHUB",
  "defaultBranch": "main",
  "accessToken": "github-token"
}
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "repositoryId": 1,
    "status": "ACTIVE"
  }
}
```

安全要求：

- `accessToken` 只允许提交，不允许查询接口返回明文。
- 后端保存前必须加密。

### 4.2 获取 Commit 列表

## 5. 知识库接口

### 5.1 上传文档

```http
POST /api/projects/{projectId}/knowledge/documents
Content-Type: multipart/form-data
```

参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| file | file | 是 | 文档文件 |
| docType | string | 是 | README / API_DOC / DB_SCHEMA / BUG_HISTORY / STYLE_GUIDE |

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "documentId": 1001,
    "status": "PENDING"
  }
}
```

### 5.2 文档列表

```http
GET /api/projects/{projectId}/knowledge/documents?page=1&size=10
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [
      {
        "documentId": 1001,
        "fileName": "order-flow.md",
        "docType": "API_DOC",
        "status": "INDEXED",
        "chunkCount": 8,
        "createdAt": "2026-05-28T12:00:00"
      }
    ],
    "page": 1,
    "size": 10,
    "total": 1
  }
```

### 5.3 删除文档

```http
DELETE /api/projects/{projectId}/knowledge/documents/{documentId}
```

响应：

```json

  "message": "success",
```

- 删除文档时需要同步删除 `knowledge_chunk`。

## 6. 审查任务接口

### 6.1 创建审查任务

```http
POST /api/projects/{projectId}/reviews/tasks
```

请求：

```json
{
  "commitId": "abc123",
  "baseCommitId": "def456",
  "branch": "main"
}
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": 2001,
    "status": "PENDING"
  }
}
```

规则：

- 如果 `commitId` 为空，默认审查最新 Commit。
- 第一版同一仓库同一 Commit 不重复创建任务。
- 如果任务已存在，返回已有 `taskId`。

### 6.2 查询任务状态

```http
GET /api/projects/{projectId}/reviews/tasks/{taskId}
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": 2001,
    "status": "RUNNING",
    "retryCount": 0,
    "commitId": "abc123",
    "createdAt": "2026-05-28T12:00:00",
    "startedAt": "2026-05-28T12:00:10",
    "finishedAt": null,
    "errorMessage": null
  }
}
```

### 6.3 重试任务

```http
POST /api/projects/{projectId}/reviews/tasks/{taskId}/retry
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "taskId": 2001,
    "status": "PENDING"
  }
}
```

规则：

- 只有 `FAILED` 或 `DEAD` 状态允许人工重试。

## 10. 前后端联调顺序

建议按以下顺序联调：

1. 登录接口。
2. 创建项目。
3. 绑定仓库。
4. 获取 Commit 和 Diff。
5. 上传知识库文档。
6. 查询文档向量化状态。
7. 创建审查任务。
8. 查询任务状态。
9. 查看报告详情。
10. 提交反馈。
11. 查询 MQ 日志和 AI 调用日志。
