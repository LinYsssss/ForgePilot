# 代码仓库智能审查平台项目初始化脚手架方案

## 1. 目标

本文档用于正式写代码前确定项目目录、模块边界、依赖选择和初始化顺序，避免一开始工程结构混乱。

## 2. 推荐仓库结构

```text

├── backend
│   ├── pom.xml
│   └── src
├── frontend
│   ├── package.json
│   └── src

│   └── app
├── deploy
│   ├── docker-compose.yml
│   ├── nginx.conf
│   ├── .env.example
│   └── init.sql
```

## 3. 后端工程方案

### 3.1 基础信息

| 项目 | 建议 |
| --- | --- |
| groupId | `com.example` |
| artifactId | `code-review-platform` |
| package | `com.example.codereview` |
| Java | 17 或 21 |
| Spring Boot | 3.x |
| 构建工具 | Maven |

### 5.1 目录结构


### 5.2 接口设计

```http
POST /predict
```

请求：

```json
{
  "diffText": "...",
  "filePath": "src/main/java/com/demo/OrderService.java",
  "changeType": "MODIFIED"
}
```

响应：

```json
{
  "riskType": "AUTH_RISK",
  "severity": "HIGH",
  "confidence": 0.81,
  "modelVersion": "v1"
}
```

## 7. Prompt 模板目录

建议后端放：

```text
backend/src/main/resources/prompts
├── code-review-system.md
├── code-review-user.md
└── json-repair.md
```

### 7.1 code-review-system.md

```text
你是资深 Java 代码审查专家。
你必须基于 Git Diff、静态分析结果和 RAG 项目上下文进行审查。
你不能编造不存在的文件、行号或证据。
你只能输出 JSON。
```

### 7.2 json-repair.md

```text
请将下面内容修复为合法 JSON。
不要添加解释，不要输出 Markdown。
```

## 8. 初始化顺序

推荐按下面顺序初始化：

```text
1. 创建 Git 仓库。
2. 保留现有 docs 目录。
3. 创建 backend Spring Boot 项目。
4. 创建 frontend Vue 项目。
5. 创建 deploy 目录和 .env.example。
6. 创建 PostgreSQL 初始化脚本。
7. 创建后端基础表迁移脚本。
8. 接入登录和项目管理。
9. 接入 RabbitMQ。
10. 接入 Git Diff。
11. 接入 RAG。
12. 接入 AI 审查。
```

## 9. 分支策略

学生项目可以简单使用：

```text
main
dev
feature/backend-basic
feature/frontend-basic
feature/rag
feature/ai-review
feature/deploy
```

如果时间紧，也可以只用 `main`，但每完成一个里程碑建议提交一次 commit。

## 10. Commit 规范

建议使用：

```text
feat: add project management api
fix: handle ai json parse error
docs: add rag design document
chore: add docker compose config
test: add review task service test
```

## 11. README 首屏内容

项目 README 第一屏建议包含：

```text
# 代码仓库智能审查平台

基于 Spring Boot、RabbitMQ、RAG 和大模型的代码仓库智能审查系统。

核心能力：
- Git Diff 异步审查
- RabbitMQ 任务调度
- PostgreSQL + pgvector 项目知识库
- 大模型生成带证据链的审查报告
- Docker Compose 服务器部署
```

## 12. 初始化完成标准

满足以下条件才算完成脚手架初始化：

- `backend` 可启动。
- `frontend` 可启动。
- `deploy/.env.example` 存在。
- `docs` 文档完整。
- README 能说明项目价值和启动方式。
- Git 工作区结构清晰。
