# 交付文档

六份面向阅读的交付文档，HTML 格式，**双击即可在浏览器打开**——自包含，无外部依赖（仅字体走 Google Fonts，离线时回退到系统字体）。

它们与 [`docs/v2/`](../v2/) 的分工不同：`docs/v2/` 是**开发时的唯一定义处**，每类事实只在一处定义；这里是**面向读者组织**的成品文档，内容引用前者，不重复定义事实。**两者冲突时以 `docs/v2/` 为准。**

## 六份文档

| 文档 | 用途 | 读者 |
|---|---|---|
| [SRS.html](./SRS.html) | 需求规格说明书：73 条功能需求 + 38 条非功能需求 + **需求追溯矩阵** | 评审、验收 |
| [TEST-REPORT.html](./TEST-REPORT.html) | 测试报告：策略、结果分布、**未覆盖部分与已知缺陷** | 评审、质量核查 |
| [SECURITY.html](./SECURITY.html) | 安全设计说明：攻击面清单 + **11 条残余风险** | 评审、安全审查 |
| [OPERATIONS.html](./OPERATIONS.html) | 运维手册：运行拓扑、健康检查、**起不来时的症状对照**、绝对不要做的事 | 部署、值班排障 |
| [MANUAL.html](./MANUAL.html) | 使用与代码手册：部署、使用流程、**主要后端类与前端文件说明**、术语速查 | 查阅 |
| [WALKTHROUGH.html](./WALKTHROUGH.html) | 跟着一次 PR 走完 ForgePilot：**12 站代码走查**，每站贴真实代码 | 第一次接触代码库 |

## 怎么读

**第一次接触这个代码库** → 先读 `WALKTHROUGH.html`。它拿一次 PR 从入口跟到结果落库，再说明人工退回/合并与通知边界，走完再查 `MANUAL.html`。

**要核对需求是否实现** → `SRS.html` 第 7 章追溯矩阵。每条需求指向设计章节、实现类、验证它的测试类。

**要了解测了什么、没测什么** → `TEST-REPORT.html`。第 8 章列出自动化覆盖不到的范围，第 9 章列出已发现的缺陷（含一条**未修复**的测试顺序依赖）。

**查某个类是干什么的** → `MANUAL.html` 第 5、6 章。承重文件（带红点标记）先给一句「它做什么」，再讲「为什么这么写」。

**要部署它，或者它半夜挂了** → `OPERATIONS.html`。第 5 章按**你实际看到的报错**组织，而不是按原因——这套系统起不来的几种方式，报错信息大多不指向真正的原因。第 8 章是不可逆操作清单，动手前先扫一眼。

## 阅读前提

这些文档假定读者**会写代码**，但**不假定**用过 Spring Boot、Vue 或 PostgreSQL。不认识的术语见 `MANUAL.html` 第 13 章或 `WALKTHROUGH.html` 末尾的术语速查（两份同一内容，38 条）。

## 关于数字

结构性数字（9 个后端包、21 张表、14 条迁移、6 个一级导航、11 条产品路由）由测试钉住。行数、文件数与用例数逐提交漂移，手册和测试报告中的数字均标明快照日期；后续引用应读取实际执行记录。

这些数字随代码变化。改动代码后若这里的数字过期，以实际执行结果为准——`docs/v2/README.md` 与各 README 中的同一组数字需要**同步更新**。
