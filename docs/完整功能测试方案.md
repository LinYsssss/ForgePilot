# RepoSage 完整功能测试方案（服务器全量部署版）

> 适用前提：Docker、PostgreSQL+pgvector、RabbitMQ、Model Service、Sandbox Runner、Nginx 全部就绪

本文件覆盖系统**每一个功能模块**的验收用例。按模块编号（M1~M14），每条用例可独立执行、独立记录结果。

### 0.2 准备账号

系统**没有注册接口**，首个账号由环境变量注入：

```
SEED_ADMIN_USERNAME=admin
SEED_ADMIN_PASSWORD=<至少 12 位强密码>
SEED_ADMIN_ROLE=ADMIN
```

测试越权需要**第二个普通账号**。若无管理界面创建用户，可临时用第二组 seed 变量启动一次，或直接在数据库插入（密码需 BCrypt）。

## M4 Pull Request（完整 7 个端点）

PR 模块共 7 个接口，是 PR 守门链路的骨架。**`POST /{pullRequestId}/review-task` 是核心** —— 它把 PR 与审查任务连起来。

| # | 用例 | 接口 | 预期 |
|---|---|---|---|
| 4-1 | **导入/创建 PR** | `POST /api/projects/{projectId}/pull-requests` | 成功，返回 pullRequestId |
| 4-2 | PR 列表 | `GET .../pull-requests` | 返回该项目下 PR，含状态与 head sha |
| 4-3 | PR 详情 | `GET .../pull-requests/{id}` | 含标题、源/目标分支、head/base sha、状态 |
| 4-4 | **更新 PR** | `PUT .../pull-requests/{id}` | 标题/状态/head sha 更新成功 |
| 4-5 | **PR head 变更** | 更新 head sha 后查看 | 关联的过期 Patch 应变为 stale（见 9-11） |
| 4-6 | **基于 PR 创建审查任务** | `POST .../pull-requests/{id}/review-task` | 成功，任务的 diff 范围是 **base..head**，不是单个 commit |
| 4-7 | **PR 审查关联知识库** | 同上，body 传 `documentIds` | 审查结果体现文档上下文 |
| 4-8 | **PR 审查幂等** | 对同一 PR 同一 head 重复创建 | 返回已有任务，不新建 |
| 4-9 | **PR 推新提交后可再审** | 更新 head sha 后再创建 | **创建新任务**（head 变了，不再幂等） |
| 4-10 | 记录审查动作 | `POST .../pull-requests/{id}/actions` | 成功写入动作记录 |
| 4-11 | 动作列表 | `GET .../pull-requests/{id}/actions` | 返回历史动作，时间倒序 |
| 4-12 | PR 与仓库归属校验 | 用 A 仓库的 PR 关联 B 仓库 | 拒绝，`errorCode` 明确 |
| 4-13 | **越权：他人项目 PR** | 账号 B 访问 | 403 |
| 4-14 | **越权：跨项目 PR ID** | A 项目 ID + B 项目 PR ID | 403/404，**不得返回数据** |
| 4-15 | 不存在的 PR | 404，`errorCode=PULL_REQUEST_NOT_FOUND` |
| 4-16 | PR 已关闭后创建审查 | 对 closed 的 PR 建审查 | 按产品语义处理（允许或拒绝），行为一致且有提示 |

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 5-9 | **索引失败保留 FAILED** | 停掉 embedding 提供方（或配错 key），上传文档 | 接口报错，但**文档记录仍在**，状态 `FAILED`，`index_error` 有脱敏原因 |

### 5.3 输入边界（Track A 重点）

准备文件：

```powershell
$d="fixtures"; New-Item -ItemType Directory -Force $d | Out-Null
[IO.File]::WriteAllBytes("$d\fake.md",[byte[]](0x4D,0x5A,0x00,0x01,0x02,0x00))       # 二进制伪装
[IO.File]::WriteAllBytes("$d\broken.md",[byte[]](0xC3,0x28,0x61,0x62))                # 非法 UTF-8
[IO.File]::WriteAllText("$d\huge.md",("x"*3145728))                                   # 3MB
[IO.File]::WriteAllText("$d\payload.pdf","hello")                                     # 不支持扩展名
[IO.File]::WriteAllText("$d\blank.md","   `n`n  ")                                    # 空白
[IO.File]::WriteAllText("$d\good.md","# 标题`n`n正常中文正文内容。")                    # 对照组
```

| # | 上传 | 预期 |
|---|---|---|
| 5-12 | `good.md` | ✅ 接受，INDEXED |
| 5-13 | `fake.md` | ❌ 拒绝：「文档内容不是纯文本」 |
| 5-14 | `broken.md` | ❌ 拒绝：「不是有效的 UTF-8」 |
| 5-15 | `huge.md` | ❌ 拒绝：超出大小限制 |
| 5-16 | `payload.pdf` | ❌ 拒绝：仅支持 Markdown 和 TXT |
| 5-17 | `blank.md` | ❌ 拒绝：内容为空 |
| 5-18 | **路径穿越文件名** | 传 `..\..\..\etc\good.md` → 接受，但**存储与展示的文件名为 `good.md`** |
| 5-19 | **被拒绝不留残留** | 5-13~5-17 之后查文档列表 | **不产生任何 PENDING 记录** |
| 5-20 | 容器级上限 | 传 10MB 文件 | Nginx / multipart 层拦截，返回明确错误而非超时 |

### 8.2 Outbox 可靠性（Track A P0-01~03 验证）

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 8-13 | **Broker 不可用不产生假 SENT** | `docker compose stop rabbitmq`，创建 Run，查 `agent_outbox_event` | 事件**不出现 SENT**，停留 PENDING/PROCESSING 并累积 attempt |
| 8-14 | **Broker 恢复后自动续跑** | 启动 rabbitmq | 事件自动转 SENT，Run 继续推进，**无需人工干预** |
| 8-15 | **租约回收** | 手工把某事件置为 PROCESSING 且 `lease_expires_at` 设为过去时间 | reaper 在一个周期内将其转回 PENDING，`attempt_count` +1 |
| 8-16 | **终态 FAILED** | 构造一个永远不可路由的事件（改 event_type 为无效值） | 达到 `max-attempts` 后转 **FAILED**，`failed_at` 有值，不再重发 |
| 8-17 | 不可路由不标 SENT | 同上过程中观察 | 全程无 SENT |
| 8-18 | 多实例不重复认领 | 启两个后端实例 | 同一事件只被一个实例发布（查 `claim_token`） |

### 8.3 Step 执行租约（Track A P0-04 验证）

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 8-19 | **执行期间无长事务** | Run 进行中，在 PG 执行 `select * from pg_stat_activity where state='idle in transaction'` | **无长时间挂起的业务事务** |
| 8-20 | **连接池不被占满** | 并发发起 5 个 Run | 连接数平稳，不耗尽 |
| 8-21 | **Worker 崩溃可恢复** | Run 执行中 `docker compose kill backend`，重启 | Step 租约过期后被 watchdog 回收，Run 继续或明确 FAILED，**不永久卡 RUNNING** |
| 8-22 | **心跳续租** | 让某 Step 执行较久（大 diff） | 该 Step **不被 watchdog 误杀**（查 `lease_expires_at` 在推进） |
| 8-23 | **重复消息不重复执行** | 手工向 `agent.step.queue` 重投同一消息 | 返回忽略，**不产生重复副作用** |
| 8-24 | 周期恢复 | 进程不重启的情况下制造一个卡死 Step | 60 秒内被 watchdog 处理（P1-04） |
