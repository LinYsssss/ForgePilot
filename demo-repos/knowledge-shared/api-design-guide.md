# 接口设计指南

> 适用范围：全部服务对外暴露的 HTTP 接口，与具体业务领域无关。各服务的专属约定见各自仓库 `docs/` 下的文档。

## 1. 统一响应结构

同一服务的所有接口使用同一种外层响应结构，成功与失败都走这一种。业务数据放在
固定的数据字段里，不得让某些接口直接返回裸数组、另一些返回包装对象。

HTTP 状态码表达协议层结果，响应体内的状态字段表达业务结果，两者职责不混用。
不得出现所有情况都返回成功状态码、靠调用方解析文案判断成败的做法。

## 2. 分页

返回集合的接口一律分页，且每页条数必须有服务端上限。上限由服务端强制截断，
不能仅在文档里写明或依赖调用方自觉，也不接受「传特殊值即取全量」这类后门。

分页参数需校验为非负整数并规定越界行为。深翻页对存储压力大，数据量大的场景
应改用游标式分页而不是无限增大偏移量。

## 3. 错误码

错误码是对外契约的一部分，必须稳定、可枚举、集中定义。同一语义的失败在任何
接口上返回同一个码，已发布的码不得改变含义，废弃时只标注不复用。

错误响应需同时给出可供机器判断的码与面向人的说明。说明里不得包含内部结构、
语句片段或调用栈。

## 4. 幂等

有副作用的写操作必须支持幂等键。调用方生成键并在重试时原样重发，服务端据此
识别重复请求，返回首次执行的结果而不是再执行一次。

幂等的判定必须落在持久化层，依赖唯一约束或条件更新，不能只靠内存标记或
分布式锁——进程重启和网络重试都会绕过它们。

## 5. 版本演进

对外契约只做向后兼容的演进：可以新增可选字段，不可以删除字段、改变字段含义
或收紧取值范围。破坏性变更必须发布新版本，与旧版本并行一段时间。

字段废弃需先标注、再观察调用方，最后下线，三步不可省略。

## 6. 参数校验

所有查询参数在进入业务逻辑前完成校验，包括类型、必填性、长度与取值范围。
枚举型参数走白名单，未在白名单内的值直接拒绝，不做静默忽略或兜底取默认值。

校验失败返回明确的参数错误，指出是哪个参数不合法，但不回显完整入参。
