# 人工验收清单（批次 3 前端）

这份清单存在的原因很直接：`.trellis/spec/frontend/quality-guidelines.md` §Design drift checklist
**本来就把响应式与视觉漂移定义为「人工在 1440 / 768 / 390 三档 CSS 像素下看」**，
而编排会话跑在一个无浏览器、无 `DISPLAY` 的容器里，`getBoundingClientRect()` 恒为 0、
jsdom 没有 `matchMedia`、当前 vitest 配置下 CSS 一个字节都不进 jsdom。

因此这一档**只能由你本人执行**。`frontend/tests/journey.spec.ts` 覆盖的是路由守卫、请求契约、
角色可见动作面与「四个标记不得合并」的 DOM 结构，**它不是浏览器验收**，
勾完下面这些格子之前，Phase 7 的「浏览器 / 可访问性 / 响应式 / 视觉漂移」四项只能记为部分通过。

预计耗时 **10 分钟**。请把每一格的实际结果（✅ / ❌ + 一句话）填回 `result.md`。

---

## 0. 起服务（约 2 分钟）

```bash
cd <repo>
docker compose up -d --build
docker compose ps          # 三个服务都应是 healthy
```

打开 <http://127.0.0.1:18081>。后端在 <http://127.0.0.1:18080>，前端 nginx 会把 `/api/` 代理过去。

准备三个账号：在登录页点「没有账号？去注册」，分别注册 `lead` / `dev` / `rev`（口令任意，≥8 位）。
**同一浏览器同时只有一个会话**（进程内 `HttpSession`），三角色演示请串行「退出登录 → 重新登录」。

三档分辨率：DevTools（F12）→ 设备工具栏（Ctrl+Shift+M）→ Responsive → 宽度依次填
**1440**、**768**、**390**。每一节都请在三档下各看一遍。

## 1. 全局外壳（1 分钟）

| # | 点哪里 | 看什么 | 什么算通过 |
|---|---|---|---|
| 1.1 | 任意页面按一次 `Tab` | 左上角是否弹出「跳到主要内容」 | 出现且有可见焦点框；回车后焦点落到正文 |
| 1.2 | 顶部导航 | 一级菜单条目数量 | **恰好三个**：项目 / 研发需求 / 代码审查。出现第四个即失败 |
| 1.3 | 390 档 | 顶栏是否换行、导航是否可横向滚动 | 顶栏纵向堆叠，导航条自身可横向滚动；**整页不出现横向滚动条** |
| 1.4 | 三档 | 页面右侧是否露出白边 / 横向滚动条 | 三档都没有页面级横向溢出 |
| 1.5 | 系统设置里打开「减少动态效果」后刷新 | 导航 hover、按钮过渡 | 过渡基本消失，内容与焦点顺序不变 |

## 2. `/projects/:id/settings` 项目设置（2 分钟）

以 `lead` 登录 → 项目页 → 某个项目的「项目设置」。

| # | 点哪里 | 看什么 | 什么算通过 |
|---|---|---|---|
| 2.1 | 「SCM 仓库配置」区 | 「访问令牌」「Webhook 密钥」两个输入框 | 输入时显示为圆点（`type=password`）；**页面任何地方都不回显已保存的凭据** |
| 2.2 | 填完注册一次 | 返回的连接信息块 | 只显示 id / 提供方 / 实例标识 / 外部 id / API 基地址 / 时间；**没有令牌、没有密钥** |
| 2.3 | 刷新页面（F5） | 连接信息块 | 变回「本页只显示本次写入返回的连接信息…」这段说明。**这是预期行为**：服务端没有查询端点。若这段说明被读成「没配过」，请在 `result.md` 记一笔 |
| 2.4 | 「项目知识」区 | 有没有上传控件 | **应当没有**，只有一段「服务端还没有对应的 HTTP 端点」的说明。若这里出现了一个点了没反应的按钮，即失败 |
| 2.5 | 「需求质量检查」区 | 选一个需求 → 运行 | 出现「检查的版本 vN」「规则集版本」「检查时间」，以及规则与 AI 两段结果；**没有分数、没有总评** |
| 2.6 | 用 `dev` 登录后再进本页 | 三个区块 | SCM 与质量检查都显示「只有项目负责人可以…」，**没有任何可点的写操作** |
| 2.7 | 390 档 | 表单字段 | 字段纵向堆叠，label 与输入框不错位，长的 API 地址不撑破页面 |

| # | 点哪里 | 看什么 | 什么算通过 |
|---|---|---|---|

| 3.2 | 选择项目 | 「需求的评审活动」区 | 每条需求一行，「评审活动」是**独立一格**，旁边是六个单 PR 状态的计数 |

| 3.9 | 三档 | 「是否当前有效」列 | 是文字「当前有效」/「已过期」，**不是只靠颜色** |

## 4. `/reviews/:id` 审查详情（3 分钟）

从上表点「审查 N」进入。这是本批次最容易违规的一页，请慢一点看。

| # | 点哪里 | 看什么 | 什么算通过 |
|---|---|---|---|
| 4.1 | 任意一条 Finding | **四个标记** | 「人工状态」「跨轮血缘」「AI 置信度」「所属 Review 的 Decision」是**四个独立的 dt/dd**。**合成一个综合风险徽章即失败** |
| 4.2 | 同上 | 「AI 置信度」的值 | 显示「未记录」。`finding` 表没有置信度列，**这里出现任何数字都说明有人编了一个** |
| 4.3 | 「审查覆盖与未审查文件」区 | 未审查文件 | 有清单就逐条列出；没有就显式写「未审查文件：0 个」。**静默不显示即失败（D002）** |
| 4.4 | 同上 | 「是否发生截断」 | 有独立一格，文字为「有内容被截断」/「没有截断」 |
| 4.5 | 「终局决定」区（用 `rev` 登录） | 两个按钮 | 「通过（APPROVE）」「退回（REQUEST_CHANGES）」；**前置不满足时按钮置灰且下面列出具体原因**，不是默默不能点 |
| 4.6 | 做一次 REQUEST_CHANGES 后 | 页面上是否出现闸门提示 | 出现「此 head 已有退回：只有新的 head SHA 能解除…」。再试 APPROVE 应被拒 |
| 4.7 | 用 `lead` 登录看同一页 | Finding 的动作按钮 | **看不到「认领」和「标记已修复」**（PRD §3 的 LEADER 列就是 ❌）。看得到即失败 |
| 4.8 | 用 `dev` 登录看同一页 | Finding 的动作按钮 | 看得到「认领」「标记已修复」；**看不到**「确认」「驳回」「重开」 |
| 4.9 | 头部「所属 PR 与需求关联」 | 下拉框（仅 `lead` 可见） | 可以改、可以选「不关联需求（清除）」；`dev`/`rev` 只看到一句说明 |
| 4.10 | 任一 Finding 点「查看审计记录」 | 列表 | 出现「时间 · 动作 · 从→到 · 操作人」，没有记录时显式说没有 |
| 4.11 | 390 档 | 长文件路径、证据摘录、上下文快照 | 路径换行不撑破页面；证据与快照在**自己的框内**滚动 |
| 4.12 | 三档 | 所有状态徽章 | 每个徽章都有文字，不是纯色块 |
| 4.13 | 只用键盘走一遍本页 | Tab 顺序与焦点框 | 顺序与视觉顺序一致，每一步都有可见焦点框，没有焦点陷阱 |
