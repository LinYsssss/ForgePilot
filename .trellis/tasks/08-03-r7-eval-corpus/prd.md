# 评测集扩充：6→30-50例，含漏报专项

> r8 提示词调优的地基：没有能度量漏报率的评测集，"调优"就无法自证。无硬前置，可与 r5/r6 并行。沿用 `evaluation/` 现有 manifest + cases 结构（6 个版本化用例、确定性输入校验），只扩容不改机制；若结构需扩展字段，保持向后兼容。

## Goal

评测集从 6 例扩到 30-50 例带标注 diff，漏报率成为独立可计算指标，形成"改 prompt → 跑评测 → 看漏报率/误报率变化"的度量能力。

## Requirements

### R1 用例构成（按审查器必须抓住的风险面配比）

| 类别 | 数量目标 | 素材来源 |
| --- | --- | --- |
| 安全类（越权/注入/密钥泄漏/CSRF） | 8-12 | demo-repos 故意缺陷改编 + 本仓库历史真实修复（如 `be59ed8` CSRF 案例脱敏改编） |
| 业务规则破坏（订单/支付流程违规） | 6-10 | demo-repos 知识文档对应的规则场景 |
| 工程质量（空指针/事务边界/资源泄漏） | 6-10 | 审计发现改编（F-02 的路径假设、F-03 的契约漂移都是绝佳素材） |
| **漏报专项：干净 diff 中埋单一深藏缺陷** | 6-8 | 人工构造：大 diff + 一处不显眼缺陷（测"捞得出来"） |
| **误报专项：完全无缺陷的正常 diff** | 4-6 | 真实正常提交脱敏（测"忍得住不报"） |

### R2 标注格式

- 每例标注：预期 findings（severity/category/file/line 区间）、允许的等价表述、判定规则（命中=模型 finding 与预期在文件+类别+行区间三要素匹配）。
- 漏报率 = 未命中的预期 findings / 预期 findings 总数；误报率 = 无对应预期的模型 findings / 模型 findings 总数。两个指标独立呈报，禁止合成单一分数（会掩盖召回换精度的作弊空间）。
- manifest 保持确定性校验（现有机制），新用例全部过校验。

### R3 基线跑分

- 扩充完成后，对当前 prompt（未调优）跑一次全量评测记录基线数字，落档本任务目录——这是 r8 一切对比的原点。
- 跑分需真实大模型（mock 模式规则引擎不读知识文档，数字无意义）；服务器上配置 MiMo 执行，记录模型名与日期。

### 硬约束

- 用例素材一律脱敏：不含真实密钥、真实个人信息、非本项目的真实业务代码。
- demo-repos 原有故意缺陷与知识文档不动（演示资产保留义务）；评测用例是独立副本。
- 标注是"预期最小集"而非"越多越好"：每个预期 finding 必须是明确可指认的缺陷，模糊的"最好也报一下"不进标注（宁精勿多同样适用于标注）。

## Out of Scope

- 评测执行框架改造（现有机制够用）；CI 集成自动跑分（属原 Phase 7 LLMOps 方向，已裁决不做；将来要做另立任务）；prompt 修改（r8）。
