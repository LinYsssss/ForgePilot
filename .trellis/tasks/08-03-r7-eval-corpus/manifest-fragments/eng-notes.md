# eng 批次创作说明（工程质量 8 例）

批次配额：development 6 / holdout 2。形态构成：F-02 启动路径 1、F-03 漂移 2（含 fence-stripper 旁路变体）、@Transactional 自调用 1、资源泄漏 2（文件句柄/HTTP client，与老例 JDBC 区分）、空指针 2（Optional.get / Map.get 链）。全部 JAVA、base-head 布局、虚构域 `com.acme.*`，不触碰 demo-repos 与原 6 例。holdout 取 fence-bypass（漂移家族独特形态）+ map-get（常见形态），两个缺陷家族各留一份防 r8 过拟合。行号已逐条 grep -n 复核（见各行锚点）。

- `eng-startup-path-assumption`（development, STARTUP_ASSUMPTION, HIGH）：素材=审计 F-02（`.trellis/spec/backend/quality-guidelines.md:24-46` 叙事改编，路径/属性名均换虚构值）；缺陷=新增 `@Service` Bean 构造器对默认绝对路径 `/var/acme/export-archives` 立即 `Files.createDirectories`，非 root 部署/CI 环境 AccessDeniedException 导致上下文起不来；HIGH 因整个服务启动失败（原事故 main 红 12 天）；锚点 `ArchiveStorageService.java:16-20`（构造器签名+默认值+createDirectories）。
- `eng-contract-drift-dual-encode`（development, CONTRACT_DRIFT, HIGH）：素材=审计 F-03（`agent-model-contracts.md:98-111` "one defense implementation per concern"）；缺陷=共享 `AssetReferenceCodec` 同一 diff 内升级为 v2 `|` 分隔+版本前缀，`ReportLinkRenderer` 的内联复制体虽同步加了 region 却仍拼老 `:` 格式，产出的引用被 legacy 回退误解析（bucket 错位）；HIGH 因下载链接指向错误对象、静默数据不一致；锚点 `ReportLinkRenderer.java:8-10`（内联拼接行 9）。
- `eng-second-path-fence-bypass`（holdout, CONTRACT_DRIFT, MEDIUM）：素材=r2 战役 run15（`agent-model-contracts.md` 开篇与 run15 段：第二条解析路径绕过共享 fence-stripper）；缺陷=head 一边加固共享 `ModelOutputs.stripCodeFence`（javadoc 明示"所有解析路径必须经过"且该 javadoc 在 diff 内），一边新增 `SummaryResponseParser` 直接把 raw 喂 Jackson；MEDIUM 因新路径遇围栏输出确定性失败但不损数据；锚点 `SummaryResponseParser.java:16-18`（parse 方法+readValue(raw)）。
- `eng-transactional-self-invocation`（development, TRANSACTION_RISK, HIGH）：素材=Spring 事务代理自调用失效经典形态（prompt-management.md 规则一可验证清单示例）；缺陷=新增 `adjustBatch` 未标注事务且循环内 `this.adjustStock(...)` 内部调用，`@Transactional` 不经代理完全失效，库存 update 与审计 append 无原子性、部分失败留不一致账；HIGH 因写路径静默丢事务；锚点 `InventoryService.java:31-39`（无注解方法签名 31 至 this 调用 39）。
- `eng-file-stream-leak`（development, RESOURCE_LEAK, MEDIUM）：素材=老例 java-sql-resource-leak 换资源类型变体（文件句柄）；缺陷=改为流式读取时 `Files.newBufferedReader` 未用 try-with-resources，普通 try 块伪装成"已处理"，正常返回/END_MARKER 早退/异常三条路径全泄漏；MEDIUM 因句柄耗尽属渐进退化；锚点 `ManifestImporter.java:21-26`（打开 21 至早退 return 26）。
- `eng-http-client-leak`（development, RESOURCE_LEAK, MEDIUM）：素材=资源泄漏第二变体（HTTP client）；缺陷=每次 send 新建 `CloseableHttpClient` 且 client/response 均不关闭（timeout/UA 加固是干扰项），连接池与 socket 随调用量泄漏；MEDIUM 同上渐进退化；锚点 `WebhookNotifier.java:27-33`（建 client 27 至 execute 33）。
- `eng-optional-get-unchecked`（development, NULL_POINTER, MEDIUM）：素材=老例 typescript-ambiguous-null 的 Java Optional 形态；缺陷=`findByUserId(userId).get()` 无 isPresent/orElseThrow，未知用户直接 NoSuchElementException 变 500（同类安全用法 orElse 就在上一个方法作对照）；MEDIUM 因单请求失败不扩散；锚点 `ProfileService.java:20-21`（badgeLabel 签名+get() 行 21）。
- `eng-map-get-deref-chain`（holdout, NULL_POINTER, MEDIUM）：素材=空指针第二变体（Map.get 后直接解引用链）；缺陷=`routesByRegion.get(normalized).primaryEndpoint().toLowerCase(...)` 未判 key 缺失，入参倒是判了 null（干扰项：显得"已做判空"），未登记 region 的租户必 NPE；MEDIUM 同上；锚点 `EndpointResolver.java:21-23`（resolve 方法，缺陷行 23）。
