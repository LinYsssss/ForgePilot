## 冗余与实现取舍

- 清理 GitHub 客户端不再使用的 `ResourceAccessException` 导入；审查人指派复用已有 `isTerminal()`，消除重复终态判断。
- 保留前端禁用说明、服务端鉴权及数据库条件更新：分别负责操作说明、授权和并发一致性，不能相互替代。未为减少表面重复而削弱闸门。
- 两个 SCM 客户端保留各自的路径、鉴权、请求和结果校验，继续共用原有门面。当前规模不需要新的通用 Provider 框架。
- AI 完成/失败事件已经在提交后发布，人工决定事件在事务内发布；相应两类监听方式具有不同事务语义，继续复用通知发送器。
- 当前阶段继续通过共享 `requirementPhase()` / `requirementHandler()` 派生，历史通过现有 Review API 读取，公共知识沿用原文存储。不增加第二套状态、历史或文档副本。
- 角色候选与名称查询规模有界于项目成员，当前没有测量证明需要缓存或额外读模型；未为此扩大改动。
