# 界面密度与对齐优化(前端第二轮)

日期:2026-10-17 · 上一轮:「工作台化改造」(已完成并部署,见 `10-17-workbench-ia/`)

## 用户反馈(逐条对应)

1. 右上角会话区不好看 → 重做。
2. 工作台「我的待办」太长,要与其他板块对齐 → 定高内滚 + 两栏等高。
3. 「公共知识文档」卡片空白太多 → 紧凑化。
4. 「仓库接入」左侧空白太多 → 布局重排。
5. 需求详情「AI 辅助」两栏没对齐、生成文本前后有空白 → 等高对齐 + 文本 trim。
6. 除参考界面外,其余板块也要按市面优秀平台的排版习惯优化(密度、对齐、动作位置)。

约束不变:沿用既有 token 与组件语汇(不新增颜色/字体)、不改路由与接口、承重文案保留、每步过四道门。

## 逐项方案

1. **会话区(AppShell)**:改成头像(displayName 首字)+ 姓名 + ▾ 的单个下拉;弹层里放账户信息、账户设置、退出登录;删除独立的「退出登录」按钮。同步更新 `journey.spec.ts` / `session.spec.ts` 中的退出路径(先开菜单再点退出),断言口径不变。
2. **工作台待办**:`.table-scroll` 定高(约 34rem)内滚,表头 `position: sticky` 吸顶,面板底部加「共 N 项」脚注;两栏 `align-items: stretch`,右栏在窄屏自然堆叠。表格行高收紧(内边距降一档)。
3. **知识页**:文档卡片改为「标题 + 状态徽标」一行,元信息压一行 muted,动作(阅读/下载/提升/删除)同排右对齐,索引详情折叠为行内小摘要;上传面板提示保留一句。
4. **仓库接入**:顶部两条提示合并为一条;「当前接入」由竖排 dl 改为自适应 facts 网格;非负责人视图把大空白换成紧凑的只读说明 + 权限提示;表单与通知面板同宽紧凑排列。
5. **需求详情 AI 标签**:`.requirement-intelligence-grid` 改 `align-items: stretch`,两面板 flex 列布局使标题行等高;新增 `prose()` 助手对模型文本 `trim()` 并折叠 3+ 连续空行,用于概览/清单/规则/风险/引用与质量检查的 AI 摘要。
6. **通用密度**:`page-head` 内边距收一档(仍用既有 token);列表卡片(`.record`)的动作行右对齐、标题与元信息行距收紧;需求列表卡片采用与知识页相同的紧凑动作行。

## 验收

- 四道门全绿(测试改动仅限退出路径)。
- 部署后用真实浏览器截图逐页对照:会话区、工作台、知识、仓库、需求详情 AI 标签,确认对齐与空白改善。

## 结果(2026-10-17 晚,已部署)

逐条对应本轮反馈,均已完成并用真实浏览器核验(截图见 `screenshots-20261017/`):

1. **会话区**:右上角改为「头像(显示名首字)+ 姓名 + ▾」的单个下拉,弹层里放账户信息、「账户设置」与「退出登录」(danger);独立退出按钮删除。`journey.spec.ts` 的退出路径同步改为「展开菜单 → 点退出」,断言口径不变。
2. **工作台待办**:`.queue-scroll` 30rem 定高内滚 + 表头吸顶 + 底部「共 N 项 · 全部需求 / 全部审查」脚注,行内边距收紧一档;整页高度 5833px → 4158px,左栏与右栏高度接近。准备清单「25/25 已就绪」的重复文案收掉。
3. **公共知识文档**:文档压成一行式卡片(标题 + 状态徽标 + 元信息 + 右对齐动作),索引详情折叠为行尾摘要;统计卡在零值时不再用信息蓝高亮。
4. **仓库接入**:顶部两条提示并为一段;「当前接入」事实列表固定三列(宽 3 / 中 2 / 窄 1),不再被 auto-fit 摊成一整行;非负责人的大虚线空态改为一行提示。
5. **AI 辅助**:两面板 `align-items: stretch` + flex 列布局,说明区预留同一高度,标题与后续内容左右对齐;新增 `prose()` 收掉模型散文首尾空白与连续空行(模板与 Markdown 导出共用),`requirement.spec.ts` 用带空白的 fixture 锁住该行为。
6. **通用密度**:`.page-head`、`.record`、`.record-actions` 的内边距/上边距各收一档;需求列表卡片元信息固定三列。

门禁:lint / typecheck / vitest 66 项(含新增 trim 断言)/ build 全绿。部署:20:19 UTC `docker compose -p fp-demo up --build --detach --wait`,前端资产 `index-QFiYJGTr.js` / `index-By-epeHB.css`,本地与公网一致;后端未改,未重跑。

## 第三轮补充(同日,已部署)

- **工作台两栏对齐的真因**:`.workbench-columns` 的行是默认 `auto`,48 行表格按内容把行撑到 4011px 并溢出容器(校准面板被压在下面)。修复 = 显式 `grid-template-rows: minmax(0, 1fr)` 把行收进定高容器(56rem),左栏在内部滚动、右栏在自身高度内拉伸(超高才内滚);右栏再压实一档(动态 3 条、间距收紧、快捷操作一行三键)。度量复核:`columns/queue/rail` 底边重合同一像素,队列 `clientHeight 573 / scrollHeight 3792`,右栏接近不滚。
- **研发需求列表**:卡片压成一行式(REQ + 标题 + REV/状态徽标 + 处理人/开发/评审/更新时间同行,动作右对齐);列表区 48rem 定高内滚(实测 `clientHeight 768 / scrollHeight 2450`,卡片高 84px)。
- **代码审查列表**:表格 46rem 定高内滚、表头吸顶、行距收紧、PR 标题单行省略(悬停看全文);实测 `clientHeight 734 / scrollHeight 6755`。
