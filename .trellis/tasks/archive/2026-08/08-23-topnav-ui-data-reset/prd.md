# 顶部导航、界面统一与演示数据重置

## Goal

将 ForgePilot 已登录界面从侧边导航调整为桌面顶部居中的六入口导航，重新组织登录页品牌视觉，并统一优化各主要页面的信息层级与留白。同时安全清理当前部署中的历史测试业务数据，只保留现有可用账号 `ysainlin`。

## Confirmed data scope

- 当前部署仅有一个账号：`user_account.id=4, username=ysainlin, enabled=true`。
- 保留该账号、密码哈希、启用状态与会话版本，不创建新的全局角色、权限表或管理员字段。
- 清空项目以及全部项目关联数据；目标包括另外 15 张业务表，清理后均为零行。
- 不删除 PostgreSQL 卷，不修改 Flyway，不新增“重置数据”HTTP 接口。

## Requirements

### R1 — 顶部居中导航

- 已登录桌面界面采用单一顶部应用栏：左侧 `logo-lockup.png`，中间六个一级入口，右侧账号与退出操作。
- 一级入口仍为工作台、项目、研发需求、项目知识、仓库接入、代码审查，路由和项目查询参数保持不变。
- 窄屏允许顶部栏分为两行，导航水平滚动；所有入口保持可达，不引入抽屉、菜单依赖或新的断点体系。
- 删除侧栏专属文案和布局，不留下空列或伪侧栏。

### R2 — Logo 与登录页

- 登录页只显示 `logo-app.png`，不再把应用图标和横版 Logo 并排堆放。
- 横版 Logo 只在已登录顶部栏承担品牌识别；应用图标继续作为 favicon。
- 登录页重新平衡品牌叙事、流程亮点与登录表单，使主操作更集中，并保持现有登录/注册行为。
- Logo 保持原比例和透明背景，不新增图片处理依赖。

### R3 — 主要页面统一优化

- 工作台、项目、研发需求、项目知识、仓库接入和代码审查统一页面标题、项目选择器、摘要卡、内容面板和空状态的层级与间距。
- AI 能力链与向量索引仍是视觉亮点，但不增加虚构指标、聊天、Agent 或第二运行流程。
- 优先整理现有过度压缩的模板与样式，使 Knowledge、Repository、Workspace 页面可维护并与其他页面一致。
- 需求详情、Review 详情等既有功能页面继承统一 Shell 与基础面板改进，不改业务交互和权限。

### R4 — 数据清理与验证

- 前端实现和自动化验证完成后再执行部署数据库清理。
- 数据清理使用一个明确的 PostgreSQL 事务，显式列出除 `user_account` 外的业务表，不使用删卷或重建数据库。
- 清理后验证 `user_account` 恰好一行且为启用的 `ysainlin`；其余 15 张业务表均为零行。
- 部署后验证 PostgreSQL、backend、frontend 健康，登录页、六入口 SPA 路由和两份品牌资源可访问。

## Acceptance Criteria

- [x] AC1：桌面顶部栏的一级导航在页面水平中心，横版 Logo 位于左侧，账户操作位于右侧；侧栏完全移除。
- [x] AC2：64rem 与 42rem 以下仍能访问六个入口，没有页面级横向溢出，项目查询参数继续传递。
- [x] AC3：登录页只可见一个应用 Logo，登录/注册、错误、pending 和键盘焦点行为保持可用。
- [x] AC4：六个一级页面拥有一致且清晰的标题、选择器、摘要/内容面板与空状态布局；AI 和向量能力仍明显。
- [x] AC5：前端不新增依赖、路由或业务状态源；lint、严格类型检查、现有聚焦测试和生产构建通过。
- [x] AC6：部署数据库只保留启用账号 `ysainlin`，其余 15 张业务表均为零行；现有 PostgreSQL 卷未删除。
- [x] AC7：更新后的 Compose 三服务均 healthy，后端和代理健康接口、登录页及六个产品路由返回成功响应。

## Out of scope

- 真正的全局管理员角色、超级管理员 API、后台用户管理页或数据库结构变更。
- 删除账号、修改 `ysainlin` 密码、禁用注册接口。
- 新 UI 框架、图标库、状态库或新的运行时依赖。
- 后端业务功能、正式评测资产、容量测试或 holdout 重跑。
