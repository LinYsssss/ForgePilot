### 1.1 两处修正（不是翻译，是内容订正）

- `JavaFindingNormalizer` / `PythonFindingNormalizer` 其实**一条注释都没有**：统计脚本把
  `"http://apache.org/xml/features/..."` 里的 `//` 误认成行注释，才让它们混进 59 的名单。
  但这两处正是「关键裸奔逻辑」——解析沙箱工具输出的 XML 时做了整套 XXE 关闭配置却零解释，
  已补中文说明（少关任一项，构造过的报告即可诱导后端读本地文件或外连）。
- `AgentOutboxScheduler` / `AgentSchedulingConfig` 的类注释原本断言「测试上下文完全不受影响」，
  该断言已被证伪（打开调度的测试上下文会被 Spring 缓存复用，其调度线程在该类结束后继续动同一张表），
  翻译时一并订正并写明前提条件。
- `AgentToolRegistry`（245 行、零注释、模型输出与真实副作用之间的收口点）补了类注释，
  说明四道闸的存在理由；文中每条断言都对着实现核过（`sanitize` 确实把命中
  `SECRET_MARKERS` 的字段递归替换成 `[REDACTED]`）。

## 2. 豁免清单（192 个文件，按形态归类）

这些文件不含中文，是因为**它们不含任何注释**，而且结构本身已经把话说完了。给它们加注释就是计划
明令禁止的「废话注释」（`/** 用户 id */ private Long userId;` 这种）。

| 形态 | 数量 | 豁免理由 |
|---|---|---|
| record / enum / DTO | 66 | 字段名与类型即全部语义，没有隐藏契约 |
| JPA 实体 | 22 | 列映射由注解自述，约束在迁移 SQL 里已成文 |
| Spring Data 仓储接口 | 19 | 方法名即查询语义（派生查询），`@Query` 处才需要解释，那些已在 §1 覆盖 |
| 接口声明 | 10 | 契约由方法签名承载；有实现语义要交代的（如 `ScmProvider`）已在 59 之列并写了中文 |
| 异常类型 | 3 | 类名即语义，触发条件在抛出点解释 |
| 其它实现类 | 72 | 见下方边界说明 |

## 3. 边界：72 个「其它实现类」不是拍胸脯的豁免

必须讲清楚：前 120 个（record/实体/仓储/接口/异常）是**结构性自明**，豁免有硬理由。
剩下 72 个实现类不一样——它们只是**现在没有注释**，不等于**不该有注释**。

本轮对其中价值最高的几处补了注释（见 §1.1）。其余没有逐个补，理由是：

- 判断「这段逻辑是否非显然」需要真读懂每个类，而不是看行数；批量加注释必然产出废话，
  违反计划的「不写废话注释」硬约束，净值为负。
- 真正需要注释的是**反直觉的决策**（为什么不用显而易见的那种写法），这类点通常在改动它的时候
  才浮现。按需补注、随改动一起补，比一次性扫平更可能写出有信息量的注释。

因此本节的诚实表述是：**这 72 个是「本轮未逐个评估」，不是「已核定无需注释」**。
下次触碰其中任何一个时，若发现其中确有反直觉决策，就地补中文注释即可。
