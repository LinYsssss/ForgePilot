# R2.5 文档复核与两条欠账收口

## Goal

以当前代码为准复核全部文档，删除生产过程中留下的无用文件，并全盘核对实现是否符合原始方案。复核中发现的两条历史欠账在本任务内各自收口——一条实现，一条决策。

## Background

用户指令：「基于我现在的代码更新所有文档包括 readme，删除多余的生产过程中产生的无用代码以及文档，然后全盘检查我目前的代码是否符合我的原始方案功能要求以及有没有什么问题。」随后明确授权继续处理复核发现的问题。

D018 的顶部导航工作此前已实现并验证，但尚未提交；本任务在其提交之后进行。

## Requirements

### R1 — 文档与代码对齐

- 全部权威文档、README、前端文档、评测文档、AGENTS/CLAUDE 的状态与数字，必须由一次真实验证得出，不引用历史数字。
- 修正文档中与代码不符的陈述：ArchUnit 规则条数、`finding`/`review`/`pull_request` 的实际列与外键、不存在的迁移文件名、归档前的 `.trellis` 路径、失效锚点。
- PRD 的产品 E2E 清单区分「自动化已证明」与「只能人工验收」，不因阶段已通过就一律打勾。
- 未兑现项集中列出，使后续会话无法把它们误当成已完成。

### R2 — 清理

- 只删除可证明无用的产物：与已跟踪资源逐字节相同的重复件、构建缓存、空目录。
- 不删除验收证据、评测不可变资产与多平台 Agent 工具链。

### R3 — 欠账一：PRD P1 的 DEVELOPER 半条授权

- PR 作者可在当前 head 尚无任何人工终局 Decision 时纠正 PR↔需求关联。
- 作者身份按项目级稳定外部 user id 判定，禁止按用户名。
- 闸门判据是「非 PENDING 的 Decision」而非「存在 Review」——自动投递本就会先建 PENDING。
- `scm` 不得在编译期依赖 `review`。

### R4 — 欠账二：向量索引

- 先实测冻结 Profile 下各索引形态是否可建，再决定做什么，不凭 D001 的原文直接补迁移。
- 结论必须落成决策记录，并有一条会在前提改变时失败的测试。

## Acceptance Criteria

- [x] AC1：后端 `./mvnw -B -ntp verify` 全绿、零 skip。
- [x] AC2：前端 lint、typecheck、test、build 四条命令全部通过。
- [x] AC3：文档相对链接零断链；文档中不再残留 307 / 3 入口 / 7 路由 / `V1__init.sql` 等与代码不符的陈述（历史快照小节除外，且已标注为历史）。
- [x] AC4：作者可纠正关联；本 head 出现终局裁定后返回 409；推新 head 后重新可改；LEADER 不受闸门影响；按用户名冒充被拒；未核验身份的成员被拒。
- [x] AC5：ArchUnit 8 项全绿，`scm` 编译期仍不依赖 `review`。
- [x] AC6：D019 落盘，并由 `KnowledgeVectorIndexTest` 钉住其实测前提；顺序扫描在冻结的 4096 维上给出精确余弦序。
- [x] AC7：未新增表、迁移、顶层包、一级入口或运行时依赖；评测不可变资产未被触碰。

## Out of scope

- 更换 Embedding Profile 或重嵌入。
- 补建有损向量索引。
- 需求状态转换审计表（D013.3 的既定缺口）。
- 正式评测重跑、容量重测、浏览器 E2E 自动化。
