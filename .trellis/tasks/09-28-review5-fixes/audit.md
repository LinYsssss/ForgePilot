# 全仓校验与整理（2026-09-30）

## 结论与边界

已完成一轮**全仓静态扫描、关键入口人工核对和最小整理**。主要发现是现行文档仍描述旧占位阶段、重复规范、注释失真和运维说明错误。本次没有找到足够证据可安全删除的业务类/函数，因此没有为凑清理量删除代码、依赖或数据。

这不是“所有业务逻辑逐行审计且无 bug”的保证；没有跑生产数据库业务验收、真实浏览器、真实模型或外部 SCM/钉钉联调。此前 review-5 自动化验证仍是当前可执行代码的基线，本轮没有重复跑全套来增加测试数字。

## 覆盖与方法

- 清单覆盖 1489 个跟踪项（包括一个指向目录的有效符号链接），另分类检查忽略生成物。
- 后端：197 个生产 Java 文件、62 个测试文件的类型/符号引用扫描；人工核对认证、项目授权、需求/SCM/审查/知识/通知入口及改动相关链路。Controller、监听器、配置类和接口实现不是因“没有类名引用”就无用。
- 前端：38 个 src 文件及 18 个测试文件的声明/引用扫描；读取实际路由、共享 session、API 路径拼接。65 个 requestJson 调用点中，64 个方法/路径由 TypeScript AST 扫描匹配后端；另一个动态 approve/reject 调用人工核对两条映射，均存在。
- 路由扫描的两个空路径候选是 webhook 的 `@PostMapping(PATH)` 常量，人工解析后分别为 GitHub/GitLab webhook；不是重复端点。Controller 70 条映射，加上安全过滤器登录/登出两条。API 文档不再重复维护错误的总数。
- 文档：docs 的 26 个跟踪文件连同根/模块入口和工程规范；其中 40 个当前 Markdown/HTML 文件检查了 161 条本地引用与 71 个 HTML 锚点，修正后无缺失文件、缺失 HTML 锚点或重复 HTML id。未联网验证外部链接，也未把所有 Markdown 标题 slug 当成经过完整渲染器验证。
- 配置：读取 compose.yaml、application.yml、.env.example、CI 与冷启动脚本。未读取部署 .env 的值，也未执行启动、清库、重启或外部写入。
